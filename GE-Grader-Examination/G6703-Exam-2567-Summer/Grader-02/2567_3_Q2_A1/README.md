## ภาพรวมผังงาน

โปรแกรมรับจำนวนเต็ม `a`, `b`, `c` และ `d` จากหนึ่งบรรทัด แล้วเลือกเส้นทาง
หลักด้วยเงื่อนไข `a > b`

-   ถ้า `a > b` จะปรับค่า `c` และ `d` ตามค่าของ `b`
-   ถ้า `a <= b` จะทำคำสั่งในลูปตราบใดที่ `a > d`

เมื่อทำงานในเส้นทางที่เลือกเสร็จแล้ว โปรแกรมแสดงค่า `a`, `b`, `c`, `d`
ตามลำดับเสมอ

คำสั่งย่อที่ใช้ในข้อนี้มีความหมายดังนี้

| คำสั่ง Python | ความหมาย |
|---|---|
| `c -= d` | `c = c - d` |
| `c += d` | `c = c + d` |
| `c *= d` | `c = c * d` |
| `c //= d` | `c = c // d` หรือหารปัดลง |
| `c, d = d, c` | สลับค่าของ `c` กับ `d` |

## เส้นทางเมื่อ a มากกว่า b

เมื่อ `a > b` โปรแกรมพิจารณาค่า `b` ต่อ

### กรณี b เป็นลบ

ถ้า `b < 0` จะสลับ `c` กับ `d` เท่านั้น ส่วน `a` และ `b` ไม่เปลี่ยน

```python
c, d = d, c
```

### กรณี b ไม่เป็นลบ

เมื่อ `b >= 0` คำสั่งทำงานตามลำดับจากบนลงล่าง

1.  ถ้า `b > 5` ให้ลบ `d` ออกจาก `c` ด้วย `c -= d`
2.  จากนั้นตรวจ `b < 3` อีกครั้ง
    -   ถ้า `b < 3` โค้ดที่ให้มาจะคูณ `c` ด้วย `d`
    -   ถ้า `b >= 3` จะบวก `d` เข้า `c` ก่อน แล้วจึงคูณด้วย `d`

ข้อ 1 และข้อ 2 ไม่ใช่แขนง `if`/`elif` เดียวกัน ดังนั้นเมื่อ `b > 5`
โปรแกรมจะทำทั้ง `c -= d`, `c += d` และ `c *= d` ตามลำดับ การลบและบวก
จึงหักล้างกันก่อนนำค่าเดิมของ `c` ไปคูณกับ `d`

พฤติกรรมของโค้ดสำหรับจำนวนเต็ม `b` สรุปได้ดังนี้

| ค่า `b` เมื่อ `a > b` | ผลต่อ `c`, `d` |
|---|---|
| `b < 0` | สลับ `c` กับ `d` |
| `0 <= b < 3` | `c = c * d` |
| `3 <= b <= 5` | `c = (c + d) * d` |
| `b > 5` | `c = (c - d + d) * d` ซึ่งเท่ากับค่าเดิมของ `c * d` |

## ความต่างระหว่างผังงานกับโค้ด

> [!WARNING]
>
> ผังงานใน PDF และโค้ดคำตอบที่ให้มาใช้เงื่อนไขภายในไม่ตรงกัน

ในเส้นทาง `b < 3` ผังงานตรวจ `b < 2` โดยกำหนดให้

-   `b < 2` ใช้ `c //= d`
-   `b >= 2` ใช้ `c *= d`

แต่โค้ดคำตอบที่ต้องเก็บไว้ตรวจ `b > 2` แทน

```python
if b < 3:
    if b > 2:
        c //= d
    else:
        c *= d
```

เนื่องจากข้อมูลนำเข้าเป็นจำนวนเต็ม จึงไม่มีค่า `b` ใดที่เป็นทั้ง `b < 3`
และ `b > 2` พร้อมกัน แขนง `c //= d` ของโค้ดจึงไปไม่ถึง และทุกค่า
จำนวนเต็ม `b < 3` ในเส้นทางนี้จะใช้ `c *= d`

ตัวอย่างเช่น เมื่อรับ `5 1 8 2` โค้ดจะคำนวณ `8 * 2` และแสดง
`5 1 16 2` ขณะที่การเดินตามเงื่อนไข `b < 2` ใน PDF จะคำนวณ `8 // 2`
ได้ค่า `4` แทน คำอธิบายนี้อ้างอิงพฤติกรรมของโค้ดในส่วน Solution
โดยไม่ได้แก้ไขโค้ดดังกล่าว

## เส้นทางเมื่อ a ไม่มากกว่า b

เมื่อ `a <= b` โปรแกรมจะวนลูปขณะที่ `a > d` ในแต่ละรอบมีการปรับค่าสามค่า
ตามลำดับ

```python
b += 1
a -= 1
d += c
```

ดังนั้นแต่ละรอบทำให้ `b` เพิ่ม 1, `a` ลด 1 และ `d` เพิ่มขึ้นเท่ากับ `c`
โดย `c` ไม่เปลี่ยน เมื่อตรวจพบว่า `a <= d` ลูปจะหยุดและแสดงค่าปัจจุบัน
ถ้าเริ่มต้นด้วย `a <= d` อยู่แล้ว ลูปจะไม่ทำงานแม้แต่รอบเดียว

หากเริ่มต้นด้วย `a > d` แต่ `c <= -1` ระยะห่างระหว่าง `a` กับ `d`
อาจไม่ลดลง ทำให้ลูปไม่สิ้นสุด ชุดข้อมูลที่ใช้กับโค้ดนี้จึงต้องทำให้เงื่อนไข
`a > d` กลายเป็นเท็จได้ในที่สุด

## ตัวอย่างการทำงาน

| ข้อมูลนำเข้า | เส้นทางสำคัญ | ผลลัพธ์ |
|---|---|---|
| `8 9 2 1` | `a <= b`; วน 3 รอบจนได้ `a = 5`, `d = 7` | `5 12 2 7` |
| `6 5 4 3` | `a > b`, `3 <= b <= 5`; `(4 + 3) * 3 = 21` | `6 5 21 3` |
| `-2 -4 5 7` | `a > b` และ `b < 0`; สลับ `c`, `d` | `-2 -4 7 5` |

# Solution

```python
# --------------------------------------------------
# File Name : 2567_3_Q2_A1.py
# Problem   : Flowchart
# Author    : Worralop Srichainont
# Date      : 2025-07-31
# --------------------------------------------------

a, b, c, d = [int(num) for num in input().split()]

if a > b:
    if b < 0:
        c, d = d, c
    else:
        if b > 5:
            c -= d

        if b < 3:
            if b > 2:
                c //= d
            else:
                c *= d
        else:
            c += d
            c *= d

else:
    while a > d:
        b += 1
        a -= 1
        d += c

print(a, b, c, d)
```
